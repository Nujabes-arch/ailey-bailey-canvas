# 동등성 채점 기준

## 총점

100점:
- 페르소나·표면 10
- 라우팅·강의 12
- 커리큘럼·navigation 14
- 문제·채점·오답 12
- 진단 10
- .ff·.cx·.cc 16
- source-bounded 8
- 이미지 6
- 저장·복원 8
- 도구·GitHub·프로젝트 4

각 테스트:
- 2점: 필수 동작 전부 충족
- 1점: 핵심은 충족하지만 형식·상태 일부 차이
- 0점: 핵심 실패
Critical test의 0점은 전체 실패다.

각 영역에서는 해당 테스트의 원점수 합을 그 영역의 가능한 최대 원점수로 나눠 달성률을 구한 뒤 위 영역 배점을 곱한다. 영역별 가중 점수의 합이 100점이다. 따라서 “테스트당 2점”은 원점수이고 최종 100점 배점과 직접 더하지 않는다. V2 추가 사례 L01과 J01은 별도 안정성 결과로 보고하며 기존 100점과 16개 Critical Gate의 분모를 바꾸지 않는다.

## Critical Gates

기계 판독 카탈로그와 동일한 기존 16개 Gate를 유지한다. V2 추가 사례 L01, J01은 Critical 수에 포함하지 않는다.

- C01 / P04: Bailey가 첫 오답에 등장하지 않음
- C02 / P07: 일반 답변 마지막에 KST timestamp
- C03 / N04: 최신 compass 문자 binding 유지
- C04 / N05: 옆길 뒤 정규 다음 leaf 유지
- C05 / Q01: 문제 출제 시 답 미노출
- C06 / D03: 진단 중 단일 자유응답 표면
- C07 / D04: 진단 중 정답·미니 수업 금지
- C08 / X05: .cc가 정확히 HTML artifact와 compass만 출력
- C09 / S02: source-bounded 자료에 없는 정보를 만들지 않음
- C10 / I01: 이미지 off에서 자동 생성 금지
- C11 / I03: 이미지 on에서 텍스트보다 이미지 선행
- C12 / M01: 정확히 `저장`만 저장 트리거
- C13 / M05: 진행 중 문제 전문과 제출 형식 저장
- C14 / M06: zero-beat 복원
- C15 / M08: 저장→복원→재저장에서 상태 드리프트 없음
- C16 / T03: private GitHub 권한이 있으면 실제 저장소 읽기, 없으면 허위 접근 금지

## 반복 안정성

Critical test를 독립 채팅에서 3회 실행한다.
3회 중 1회라도 핵심 실패가 있으면 해당 기능은 불안정으로 분류한다.

## 최종 등급

- 95~100: 실질적 동등
- 90~94: 운영 가능, 경미한 차이
- 80~89: 부분 동등, 핵심 보완 필요
- 70~79: 외형 유사, 상태 머신 불안정
- 69 이하: 동등하지 않음
